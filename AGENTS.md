# Country Proxy — правила AI-разработки

Этот repo имеет идентификатор `REP-006` в Personal AI Workspace. Бизнес-контекст
находится в связанной карточке продукта/проекта, а этот файл задаёт технические
правила именно для исходников.

Машинный bridge, если он настроен, находится внутри Git metadata по пути,
возвращаемому `git rev-parse --git-path personal-ai-workspace/local.json`. Он
указывает на Personal AI Workspace и точный Context Pack, но не копирует vault в
repo. Если путь недоступен текущему клиенту, попросить
владельца прикрепить конкретные заметки; не сканировать соседние директории.

## Перед изменением

1. Прочитать `README.md`, `repo-manifest.json` и применимые документы из `docs/`.
2. Проверить Git status и сохранить пользовательские изменения.
3. Сформулировать результат и минимальный набор затрагиваемых файлов.
4. Не читать `.env`, credentials, дампы и чувствительные данные без отдельной
   необходимости и разрешения.

## Проверка

Канонический набор проверок находится в `project-checks.json`:

```bash
python3 scripts/check.py --list
python3 scripts/check.py --execute-reviewed <review-digest-from-list>
```

Runner только фильтрует окружение, ограничивает вывод и завершает оставшуюся
POSIX process group после normal exit или timeout. Отделившийся через `setsid`
процесс он не удерживает. Флаги network/write — явные acknowledgements, а не
техническая изоляция. Для недоверенных проверок владелец обязан отдельно включить
OS/container sandbox и сетевую политику.

Не объявлять работу готовой, если применимые проверки не выполнены или их
ограничения не названы явно.

## Полномочия

- Локальные изменения кода выполняются по запросу владельца.
- Установка зависимостей, сетевые проверки и команды, меняющие файлы, имеют
  отдельные флаги runner и выполняются только когда нужны задаче.
- Commit, push, deploy, production-изменения и внешние сообщения не следуют из
  разрешения изменить локальный код.
- Секретные значения запрещены в repo, промптах, логах и примерах.

## Документация

- Изменение технических границ обновляет `docs/architecture.md`.
- Существенный выбор оформляется новым ADR в `docs/decisions/`.
- Изменение эксплуатации обновляет `docs/runbook.md` и rollback.
- Краткий продуктовый статус возвращается в Personal AI Workspace ссылкой, без
  копирования исходников в Obsidian.
