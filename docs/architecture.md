# Архитектура

MV3 service worker → Native Messaging (stdio) → Python asyncio → восемь источников с country filter → curl с валидным HTTPS → проверенный адрес → chrome.proxy.settings → контрольный fetch из Chrome.

Native helper не принимает браузерный трафик и не открывает HTTP-порт управления. Chrome запускает его через manifest с одним точным `allowed_origins`. Расширение не читает страницы/историю/пароли. Разрешения: proxy, storage, nativeMessaging, alarms, privacy и два HTTPS-хоста для проверки. Страны и выбранный регион хранятся локально. ISO-каталог задаёт допустимые коды; пользовательский список не ограничен defaults. Ни один адрес прокси не зашит в код.

Список кандидатов недоверенный: разрешены только глобальные literal IPv4, порт 1–65535 и четыре известных протокола; не разрешены логины, hostnames, локальные или metadata endpoints. Списки объединяются по очереди между провайдерами до 120 уникальных комбинаций. Ошибка одного источника не отменяет остальные; кэш разделён по стране и источнику. Контракты и ограничения: [sources.md](sources.md). Максимум десять кандидатов одновременно, у каждого два запроса; два прохода с разными таймаутами. SOCKS5 использует удалённое DNS, SOCKS4 — локальное. TLS не отключается. Страна источника лишь фильтр; страна выхода обязательна в ответе HTTPS trace.

Контроллер сериализует мутации Chrome и использует generation ID. Запоздалое health-предупреждение об уже отклонённом или заменённом адресе игнорируется. Смена страны/отключение немедленно отменяет browser probe и делает старые события недействительными. Backend отменяет старую сессию и curl-процессы. Первая ошибка активного адреса перепроверяется; вторая блокирует маршрут и запускает подбор, исключая старый адрес на три минуты. Отклонённый браузером адрес также исключается временно. Нет прямого fallback: ожидание использует недоступный loopback-прокси, маршруты HTTP/HTTPS/fallback направляются одинаково, implicit loopback bypass вычитается. localhost в браузере тоже будет недоступен при включённом режиме.

Native port поддерживает worker; после потери помощника настройки остаются блокирующими. Alarm переподключает каждые 30 секунд. При новом запуске Chrome сохранённое enabled запускает новую проверку. Внешнее управление настройками (другая extension / enterprise policy) даёт явную ошибку. Статус «Подключено» появляется после браузерной проверки. Повторная браузерная проверка выполняется на health-событии раз в минуту и по chrome.proxy.onProxyError; ошибка двух контрольных HTTPS-запросов вызывает замену, даже если curl всё ещё видит upstream.

## Решение об upstream

В trial 2026-10-27 норвежский HTTP-прокси отвечал через curl за 19–23 секунды, но дополнительный RotatingServer библиотеки завершался ошибкой. Причина не доказана. Здесь библиотека служит источником адресов; Chrome подключается непосредственно к upstream. Увеличенный таймаут применяется ко всем странам. Это не гарантирует наличия бесплатного адреса в конкретной стране.


## Резервный пул 0.2.0

`native/pool.py` поддерживает до двух резервов в памяти текущей Session. Резервы
имеют выбранную страну и отличаются от основного/друг друга по host и exitIp.
Адрес не записывается в долговечный пул: после stop, смены страны или перезапуска
помощника список строится заново. TTL 90 секунд отсчитывается монотонными часами
от завершения native-проверки. Источники и критерии HTTPS/TLS/GeoIP общие с
основным поиском.

Обслуживание перепроверяет резерв и пополняет свободные места. Между циклами
пауза 30 секунд; пополнение ограничено 45 секундами и тремя проверками
одновременно. Длинный список обходится с продолжением позиции в следующем
цикле. Проверка основного адреса выполняется независимо. До foreground-поиска
фоновая задача отменяется вместе с дочерними проверками. При смене страны/stop
не остаётся задач прежнего пула.

После отказа весь host исключается на 180 секунд, включая другие протоколы и
порты. Сбой резервного адреса исключает его host на 60 секунд. Свежий резерв
всегда повторно проверяется перед использованием; изменение страны или совпадение
выходного IP с предыдущим основным исключает его. Chrome затем выполняет свой
обычный probe, сохраняя блокировку до подтверждения. Если резерва нет или он
не прошёл проверку, начинается полный поиск. Запрос rotate, пришедший во время
успешной native health-проверки, имеет приоритет над её поздним результатом.

Native-событие pool сохраняется отдельно от основного статуса и не меняет
маршрут. Счётчик показывает только проверку помощником; он не объявляет резерв
подключённым в Chrome. UI скрывает истёкший счётчик. Фоновая проверка Chrome через
каждый резерв потребовала бы переключать глобальный маршрут профиля, поэтому
она выполняется только при фактическом выборе адреса. Новых разрешений нет.

Решение и ограничения: [0002-session-reserve.md](decisions/0002-session-reserve.md).
