# Архитектура

## Изменения после review 20 ноября 2026 — Unreleased

Приёмка точного нового комплекта [ожидается](verification.md). Следующий договор
относится к изменяемым исходникам, а не к опубликованному ZIP v1.0.0.

Отдельные persistent dynamic DNR rules priority 4 запрещают специальные назначения
выше session allow priority 3. Они действуют при поиске, connected, recovery и
после restart до Stop: `localhost`/поддомены/конечная точка, `127.0.0.0/8`,
`169.254.0.0/16`, `::1`, `fe80::/10`, `0.0.0.0`, `::` и `::ffff:0:0`,
включая IPv4-mapped формы loopback/link-local.
Блокируются HTTP/HTTPS и WS/WSS handshakes; alternate URL forms канонизирует Chrome.
Это ограниченный URL-контракт, а не DNS-resolution firewall для всех private IP.
Активный candidate сохраняет implicit bypass Chromium (`bypassList: []`),
одновременный DNR deny не даёт ему стать DIRECT-доступом к локальным сервисам.
Только блокирующий placeholder сохраняет `<-loopback>` как дополнительную
защиту при ошибке DNR. Stop удаляет и обычный hold, и special deny.

До допуска контроллер проверяет эффективные значения
`webRTCIPHandlingPolicy=disable_non_proxied_udp` и
`networkPredictionEnabled=false`, затем повторно проверяет при изменениях.
Безопасное значение другого владельца допустимо; небезопасное или непроверяемое
даёт локальную ошибку и закрытый gate. Внешний proxy/privacy change инициирует
отзыв допуска до сериализованного teardown и ожидания `stopNative`.
Между внешним изменением, доставкой уведомления и завершением DNR update остаётся
асинхронное окно: независимые API Chrome не дают атомарности и не отзывают
отправленные запросы или открытые соединения. Чужие proxy-настройки не меняются.
Пользовательский порядок восстановления — в [runbook](runbook.md#локальные-адреса-и-конфликт-настроек).
Решение — [ADR 0021](decisions/0021-special-destinations-and-effective-privacy.md).

## Базовая архитектура

Снятие записи резерва фиксируется отдельно от суммарных ошибок кандидатов.
Результат перепроверки связывается с поколением пула, конкретной записью и её
токеном до очистки, которая может сработать из-за карантина. В расширение
передаются последние 20 событий с непрозрачным идентификатором записи, временем,
этапом и допустимыми полями результата. Устаревший ответ не объясняет снятие новой
записи того же адреса. Прерванная проверка не создаёт сетевой причины; успешное
обновление и использование резерва не создают событие потери. Наблюдатель
публичного теста читает эти же события, а не угадывает причины по соседним запросам.

MV3 service worker → Native Messaging (stdio) → Python asyncio → восемь источников с country filter → curl с валидным HTTPS → проверенный адрес → chrome.proxy.settings → контрольный fetch из Chrome.

Native helper не принимает браузерный трафик и не открывает HTTP-порт управления. Chrome запускает его через manifest с одним точным `allowed_origins`. Расширение не читает страницы/историю/пароли. Разрешения: proxy, storage, nativeMessaging, alarms, privacy, declarativeNetRequest и два HTTPS-хоста для проверки. Избранные страны и разрешённый набор стран хранятся локально. ISO-каталог из 249 кодов задаёт допустимый выбор; избранное не ограничивает подключение. Ни один адрес прокси не зашит в код.

Перед применением candidate закрывается отдельный DNR gate для новых обычных
HTTP/HTTPS-запросов и WebSocket handshakes. Собственные GET/XHR к двум точным
контрольным URL остаются разрешены; обычная страница к тем же URL блокируется.
После успешных проверок HTTPS/страны/действующего маршрута текущего предложения
добавляется session-only разрешение. Сохраняемая динамическая блокировка
переживает restart/upgrade, а разрешение — нет. Stop снимает оба вида правил.
При takeover автоматическое восстановление приостановлено, gate закрыт без
изменения чужих proxy-настроек. Stop снимает собственную защиту; явный Connect
после устранения конфликта требует нового полного подтверждения Chrome.
Правила не отзывают уже отправленные запросы, не переигрывают заблокированные
формы и не превращают расширение в VPN. Полный договор и границы API —
[ADR 0018](decisions/0018-preconfirmation-traffic-gate.md).

Popup не считает сохранённый `connected/browser.ok` достаточным для текущего
подключения. При отрисовке он отдельно читает действующий собственный маршрут и
session admission, сверяет выбранный набор и страну доказательства. Несовпадение
или ошибка чтения убирают зелёный статус и текущий IP, оставляя Stop. Это
read-only представление: оно не меняет доказательства, настройки или gate и не
заменяет сетевые проверки контроллера. Независимые чтения API не атомарны;
между отрисовками маршрут может измениться.

Список кандидатов недоверенный: разрешены только глобальные literal IPv4, порт 1–65535 и четыре известных протокола; не разрешены логины, hostnames, локальные или metadata endpoints. Списки объединяются по очереди между провайдерами до 120 уникальных комбинаций. Ошибка одного источника не отменяет остальные; кэш разделён по стране и источнику. Контракты и ограничения: [sources.md](sources.md). Максимум десять кандидатов одновременно, у каждого два запроса; два прохода с разными таймаутами. SOCKS5 использует удалённое DNS, SOCKS4 — локальное. TLS не отключается. Страна источника лишь фильтр; страна выхода обязательна в ответе HTTPS trace.

Контроллер сериализует мутации Chrome и использует generation ID. Запоздалое health-предупреждение об уже отклонённом или заменённом адресе игнорируется. Смена страны/отключение немедленно отменяет browser probe и делает старые события недействительными. Backend отменяет старую сессию и curl-процессы. Первая ошибка активного адреса перепроверяется; вторая блокирует маршрут и запускает подбор, исключая старый адрес на три минуты. Отклонённый браузером адрес также исключается временно. Нет прямого fallback: ожидание использует недоступный loopback-прокси, маршруты HTTP/HTTPS/fallback направляются одинаково. Отдельный договор special destinations и implicit bypass в Unreleased указан выше; прежняя конфигурация v1.0.0 сама по себе не обеспечивала запрет localhost URL после допуска.

Native port поддерживает worker; после потери помощника настройки остаются блокирующими. Alarm переподключает каждые 30 секунд. При новом запуске Chrome сохранённое enabled запускает новую проверку. Когда помощник отзывает предложение, его номер сразу становится недействительным. Соответствующая проверка прерывается, и позднее подтверждение не применяется к следующему адресу. Расширение следит за изменениями настройки прокси обычного профиля. Перед повторным использованием результата и после HTTPS-проверки оно сверяет владельца и действующие правила маршрута. Потеря управления прерывает проверку и отображается как ошибка профиля, не как отказ адреса.

Отключение сохраняет намерение пользователя до освобождения настроек. При запуске выключенного профиля worker также очищает записи этого расширения (прокси, WebRTC, предзагрузка) и будильник. Поэтому прерванная очистка повторяема и для профилей старой версии; состояние «Отключено» публикуется после завершения очистки. Статус «Подключено» появляется после браузерной проверки. Плановая браузерная перепроверка выполняется на очередном health-событии, если после последней прошло не менее 60 секунд, а также по chrome.proxy.onProxyError; ошибка двух контрольных HTTPS-запросов вызывает замену, даже если curl всё ещё видит upstream.

Источники контрактов, проверены 2026-10-27:
- [Chrome proxy](https://developer.chrome.com/docs/extensions/reference/api/proxy)
- [Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)
- [Service worker lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)
- [proxy-scraper commit b1ade5b](https://github.com/maximilianfeix/proxy-scraper/tree/b1ade5b4aa0627ccbb193dcd9d36a621c0a22aeb)

## Выбор страны и избранное

`countries.json` — общий каталог допустимых ISO-кодов для UI, background и helper.
Popup ищет по русскому/английскому названию и коду, сортирует по русскому названию;
точное совпадение ISO показывается первым. Каталог описывает доступный выбор,
а наличие живого адреса устанавливается только проверкой выбранной страны.
Открытие меню и ввод запроса не запускают сетевой поиск.

В `chrome.storage.local` поле `countries` хранит избранное, включая пустой массив;
`selected` — последнюю явно выбранную страну либо `null`; `enabled` — намерение
подключаться. Новая установка начинает с пустого избранного, `selected: null`
и выключенного подключения. Прежние валидные настройки сохраняются. Сообщение
`settings` меняет только избранное; `connect` принимает любую страну каталога
и запускает поиск. Звёздочка не подключает и не переключает страну.

Избранное изменяет один сериализованный writer в background: `settings`
принимает проверенные `add`/`remove` и применяет их к свежему `countries`.
Полная замена списка из устаревшего UI-снимка не допускается. Настройки хранят
локальные намерения отдельно от последнего сохранённого списка; внешнее
обновление не стирает черновик, а завершение Save не поглощает более поздние
правки. Для одной страны действует последнее принятое явное изменение.
Ошибка записи относится к настройкам и не меняет статус подключения.
Договор и проверки — [ADR 0019](decisions/0019-concurrent-favorites.md).

Если сохранённое включённое состояние содержит недопустимую страну, маршрут
остаётся заблокированным и UI сообщает ошибку до явного выбора или отключения.
В режиме одной страны резерв, повторный поиск и восстановление после перезапуска
используют её же. Решение об отдельном избранном — [ADR 0005](decisions/0005-country-selection.md).

## Отзыв допуска и восстановление worker

Native health сохраняет тип отрицательного результата в адресованном `health`.
При объединении двух HTTPS-контролей уже завершённый валидный trace со страной
вне набора имеет приоритет над транспортной ошибкой второго контроля. Порядок
получения этих результатов не меняет решение об отзыве допуска. Незавершённый
trace не задерживает сообщение об отказе; оставшиеся задачи отменяются и
очищаются в прежних границах deadline. Успех по-прежнему требует обоих контролей.
Явная страна вне выбранного набора и отзыв текущего предложения начинают закрытие
обычного допуска до очереди pool/storage. Старое Chrome-подтверждение, включая
выполняющееся, больше не допускает трафик; следующий native success требует
нового Chrome proof. Сигнал сопоставляется с generation/attempt/endpoint, также
когда offer ещё ожидает controller queue. Завершение защитных вызовов входит
в barrier перед новым Start/Stop/допуском. Транспортная перепроверка перед
заменой сохраняется.

Валидный Stop принимается до startup ready и не ждёт каталога; старое
восстановление отменяется. Более новый явный Connect после готовности каталога
разрешён. Границы и решение — [ADR 0022](decisions/0022-health-withdrawal-and-startup-stop.md).

Сбой cleanup остаётся ошибкой Stop, даже если запись `stopError` также отказала:
контроллер делает один дополнительный диагностический write, затем возвращает
обработанную ошибку без замены на generic connect error. Сохранённый `stopping`
тоже оставляет в popup повтор отключения. Повторные записи и поздние результаты
подчиняются generation ID; статус `off` требует успешной очистки и записи.

Разовая ошибка чтения настроек при startup не делает каталог недоступным на всю
жизнь worker: явный Connect или изменение избранного повторяют необходимую
инициализацию. Такой повтор не воспроизводит сохранённый автостарт; более новый
Stop отменяет ожидающее подключение. Ошибка отмечается как локальная, чтобы UI
предлагал явное восстановление.
Конфликт владельца, уже замеченный в текущем bootstrap, сохраняется отдельно от
свободной настройки. Его освобождение до завершения чтения настроек не разрешает
автоматически захватить маршрут: нужен явный повтор. Обычный новый worker со
свободной настройкой продолжает восстановление сохранённого enabled через полную
проверку. Это не блокировка по истории конфликтов предыдущих worker.

## Равноправный набор стран

Дополнительный режим сохраняет `selectionMode: multiple`, `selectedCountries`
как отсортированный непустой набор ISO-кодов и `selected: null`. Порядок массива
канонический, а не приоритетный. Одиночный режим хранит `selectionMode: single`,
`selected` и массив из одного элемента. Старые одиночные настройки читаются;
неверный включённый набор блокируется целиком, без удаления части стран или
перехода к старому `selected`. Избранное остаётся в отдельном `countries`.

Native start получает весь набор; status связывается с generation ID и точным
набором `countries`. `country` описывает фактический выход, а не страну-приоритет.
Native HTTPS и browser probe принимают только выход внутри набора. Запоздалые
события другого набора/поколения не применяются. UI показывает разрешённый набор
отдельно от фактической страны; редактирование требует явного применения.

При старте сессии помощник один раз перемешивает выбранные страны. В каждом
проходе между ними распределяются до 120 проверяемых адресов; остаток квоты
переходит по кругу. Внутри страны работают такие же доли провайдеров, общие
для зеркал. После завершения списка его адреса сразу попадают в очередь.
Пока источник не ответил, его долю не занимает более быстрый сосед. Неиспользованная
доля высвобождается при завершении или истечении срока соответствующего поиска.

Одновременно работают до трёх стран, шести загрузок списков и одного библиотечного
процесса. Через 45 секунд завершается сбор новых списков; уже допущенные проверки
адресов, включая медленный повтор, имеют свой таймаут. При успехе ненужные
проверки и загрузки отменяются до передачи соединения следующему владельцу.
Готовые списки и ограниченная очередь адресов пригодны для пополнения резерва;
задачи предыдущего прохода не продолжаются скрыто. Подробности —
[ADR 0009](decisions/0009-streaming-discovery.md).
Общий резерв вмещает до двух адресов из всего набора. При отказе помощник
проверяет их одновременно и передаёт Chrome первый успешно проверенный адрес.
Порядок выбранных стран и страна текущего выхода на этот выбор не влияют.
Работающий адрес сохраняется до отказа или ручной замены. [Выбор стран](decisions/0006-equal-country-set.md).

## Решение об upstream

В trial 2026-10-27 норвежский HTTP-прокси отвечал через curl за 19–23 секунды, но дополнительный RotatingServer библиотеки завершался ошибкой. Причина не доказана. Здесь библиотека служит источником адресов; Chrome подключается непосредственно к upstream. Увеличенный таймаут применяется ко всем странам. Это не гарантирует наличия бесплатного адреса в конкретной стране.


## Резервный пул 0.2.0

`native/pool.py` поддерживает до двух резервов в памяти текущей Session. Резервы
имеют страну внутри выбранного набора и отличаются от основного/друг друга по host и exitIp.
Адрес не записывается в долговечный пул: после stop, смены страны или перезапуска
помощника список строится заново. TTL 90 секунд отсчитывается монотонными часами
от завершения native-проверки. Источники и критерии HTTPS/TLS/GeoIP общие с
основным поиском.

Для каждой записи следующая проверка назначается на 30 секунд после последнего
успеха по монотонным часам. Отдельная задача пополняет свободные места: ожидание
источника или медленной проверки не задерживает обслуживание готовых резервов.
Потоковое пополнение Session проверяет до семи кандидатов одновременно,
используя существующую ёмкость speculative в общем бюджете. Каждый кандидат
проходит полную slow-проверку обоих HTTPS-сервисов и страны выхода; таймауты
не сокращаются. Отдельный совместимый адаптер готового списка, не используемый
Session, сохраняет три проверки и собственный предел длительности прохода.
Незавершённые кандидаты сохраняют очередь: ещё не начатые идут перед прерванными,
а завершённые неудачи — после них; изменение порядка источника её не сбрасывает.

Одна Session управляет общим лимитом десяти native-проверок. При подключённом
адресе выделены один слот health, два для резервов и семь для поиска; поиск
не занимает выделенные слоты. Без активного адреса foreground-поиск использует
до десяти. Слот охватывает всю проверку адреса с двумя обязательными HTTPS-контролями.
Одинаковая незавершённая проверка не дублируется; fast/slow одного endpoint
не исполняются одновременно. Страны набора не получают приоритет от этих ролей.

Для slow-проверки имеющегося резерва каждый ещё ожидающий origin через пять
секунд может запустить один дополнительный curl. Исходный запрос продолжает
работать. Два общих nonblocking-разрешения Session ограничивают добавочные
запросы: максимум 20 основных и два дополнительных контрольных curl одновременно.
Загрузка списков имеет собственные прежние ограничения и не входит в этот счёт.
Занятое разрешение не создаёт очередь повторов и освобождается после завершения
дочернего процесса. Быстрые проверки, поиск новых адресов, пополнение и health
не получают дополнительных запросов. Если reserve присоединился к уже
созданной foreground-проверке, её политика не меняется. Правила первичного
отказа, проверок и общего supervisor — в
[ADR 0015](decisions/0015-native-reserve-latency.md).

При первичном curl97 у SOCKS4/5 готового резерва разрешён один немедленный
повтор того же HTTPS-контроля. Он делит разрешение с пятисекундным таймером:
третьей передачи не бывает. Исходные 47 секунд и оба обязательных HTTPS
сохраняются. Окончательные ошибки TLS/HTTP/страны/trace, включая уже завершившуюся
ошибку параллельной попытки, не перекрываются её успешным ответом. Карантин и
срок свежести меняются только по окончательному результату полной перепроверки.
Это узкое дополнение к первичному отказу из 0015 описано в
[ADR 0016](decisions/0016-reserve-handshake-retry.md).

Actual primary curl28 при той же reserve slow-проверке может дождаться уже
запущенного extra того же origin. На таймауте новый curl/permit не создаётся;
нет extra или он уже неуспешен — окончательный отказ. Все hard veto, оба
HTTPS и исходный47с сохраняются. Это может дольше занимать выделенную ёмкость,
но не увеличивает число запросов. Политика и пределы —
[ADR 0017](decisions/0017-reserve-existing-timeout-attempt.md).

Истёкший резерв немедленно исключается из ready-счётчика, даже если его проверка
ещё выполняется. Ошибка не продлевает TTL. Результат применяется только к живому
поколению и той же записи, с повторной проверкой страны, host и exitIp. Stop и
смена набора отменяют принадлежащие сессии задачи и ждут завершения cleanup,
включая повторную отмену во время очистки. При замене обслуживание останавливается,
а ещё свежие записи сохраняются для повторной проверки перед использованием.
[Решение и границы](decisions/0008-independent-reserve-maintenance.md).

Диагностика резерва получает наблюдения из очереди пополнения, проверки
кандидата и решения о добавлении. Повторный опрос пригодности одного кандидата
в том же проходе даёт один пропуск до проверки. Для совпадения по выходу
нужен успешный ответ проверяемого адреса. Счётчики адресных предложений и
ответов Chrome относятся ко всей сессии. В окно передаются стадия и агрегаты.
Ключи кандидатов для подсчёта повторов хранятся в памяти помощника до заданного лимита.

После отказа весь host исключается на 180 секунд, включая другие протоколы и
порты. Сбой проверки резерва исключает его host на 60 секунд. Если endpoint history
уже запретила адрес, пауза привязывается к завершённому отказу актуального lease
до возможного prune; остальные отказы обрабатываются до prune в maintenance.
Отменённый waiter общей проверки не считается её владельцем. Пауза проверяет
актуальность каждого владельца, token/generation, TTL, выбранные страны и конфликт
с активным выходом; одна запись сохраняет одну причину удаления. Общая endpoint
history по-прежнему учитывает завершённые физические проверки независимо от lease.
Завершение maintenance публикует актуальный снимок своего поколения, даже если
prune уже удалил запись: интерфейс и журнал не сохраняют прежний готовый резерв.
Если успешный health меняет host или выходной IP активного адреса, Session
синхронно пересчитывает совместимость резерва и публикует pool перед connected.
Совпавший выход снимается один раз с исходным lease ID, независимый резерв
сохраняется. Неизменный host/exit не запускает дополнительный пересчёт.
Отдельно от временных пауз recovery не принимает кандидата с host или выходным
IP предыдущего активного маршрута. Истечение паузы не отменяет это правило;
Stop и новое подключение начинают новую сессию с полными проверками.
При выборе резерва
проверяются срок годности, фактическая страна, адрес сервера и отличие выхода
от предыдущего активного. При первой удачной проверке помощник завершает
оставшуюся работу. Chrome устанавливает один маршрут и проверяет через него HTTPS.
Подтверждение и отказ содержат идентификатор сессии, номер предложения и адрес.
До первого подтверждения каждого предложения получение новых резервов
приостановлено. Это не пауза на любую последующую перепроверку того же
предложения: после первого confirm начатое фоновое пополнение может продолжаться,
пока Chrome заново проверяет маршрут. Лимит семи speculative checks ограничивает
одновременную работу, а не их общее число за восстановление; слоты native health
и maintenance остаются отдельными. Обычный трафик всё равно требует нового
подтверждения Chrome после отзыва допуска. Действующий второй
резерв остаётся доступным для следующей попытки. При замене новые адреса ищутся
одновременно с перепроверкой резерва. Первый допустимый результат любой ветки
передаётся Chrome после завершения отмены остальных задач. При наличии резерва
поиск использует до восьми из десяти слотов, оставляя два для перепроверок;
один потоковый планировщик сохраняет равноправие стран и источников. Успешный
независимый второй результат сохраняет фактическое время проверки. После
подтверждения Chrome пополнение возобновляется; освобождение места будит его,
а пустой проход повторяется с обычным интервалом. [Условия замены](decisions/0010-parallel-reserve-checks.md)
и [параллельный поиск](decisions/0013-parallel-recovery-discovery.md).

Native-событие pool сохраняется отдельно от основного статуса и не меняет
маршрут. Счётчик показывает только проверку помощником; он не объявляет резерв
подключённым в Chrome. UI скрывает истёкший счётчик. Фоновая проверка Chrome через
каждый резерв потребовала бы переключать глобальный маршрут профиля, поэтому
она выполняется только при фактическом выборе адреса. Новых разрешений нет.

Решение и ограничения: [0002-session-reserve.md](decisions/0002-session-reserve.md).


## Надёжность 0.2.1

Принудительная браузерная перепроверка относится только к актуальному active
endpoint. Отложенное событие с прежним адресом не устанавливает его повторно
после replacing или выбора B. Потеря Native Messaging немедленно инвалидирует
поколение: queued события старого port не могут менять маршрут.

Браузерная перепроверка одного и того же актуального предложения объединяет
события, поступившие, пока его HTTPS-проверка ещё выполняется. Ключ учитывает
поколение, номер попытки, endpoint, native country/exitIp и весь набор стран.
После завершения сетевой проверки новое событие требует нового probe, даже если
предыдущий обработчик ещё ждёт сверки маршрута или отправки подтверждения.

Browser probe возвращает наблюдаемый exitIp/country и структурированную причину
отказа; popup сохраняет последнюю ошибку до следующего подтверждённого подключения
или нового выбора страны. Два HTTPS-хоста, валидные сертификаты и принадлежность
страны выбранному набору остаются обязательными. Через пять секунд для каждого
ещё не завершившегося HTTPS-контроля допускается один дополнительный запрос к
тому же origin через действующий прокси. Всего не более четырёх запросов; общий
таймаут остаётся 50 секунд от начала probe. Исходный запрос продолжает работать.
Первый успешный ответ конкретного сервиса отменяет его лишний запрос, но успех
всего probe требует обоих сервисов. Окончательный отказ исходного запроса или
полученный до завершения контроля неверный HTTP/trace/country прерывает проверку.
Транспортный отказ только дополнительного запроса не мешает ещё работающему
исходному. Отмена относится к fetch; жизненным циклом внутренних соединений
управляет Chrome. [Решение и границы](decisions/0014-browser-probe-latency.md).

Native проверка возвращает ограниченную диагностическую категорию, без тел
ответов и stderr. Session агрегирует число попыток/успехов/причин отказа только
в памяти; копия счётчиков сопровождает статус в Chrome local storage. Попытки
включают быстрые/медленные повторы, active health и резерв. Ошибка отдельной
проверки или временный сбой discover не завершает сессию; поиск повторяется.

## История проверок

Помощник ведёт историю по протоколу, IP и порту в каталоге `--data-dir`.
При обычной установке каталог выбирается по корню Chrome `user-data-dir`,
к которому относится регистрация Native Messaging. Это не отдельная история
для каждой вложенной папки `Default`/`Profile N`: использующие одну регистрацию
профили могут обращаться к общему каталогу. Настройки расширения и маршруты
при этом остаются в своих профилях. Без `--data-dir` история существует только
в памяти; занятый или недоступный каталог также даёт временную работу в памяти.
Быстрая проверка и её медленный повтор дают один итог. Повторные неверные
ответы trace увеличивают паузу от минуты до часа. Неоднозначные сетевые
ошибки дают минутную паузу. Смена страны выхода обновляет подсказку о географии.
Первый неудачный health активного маршрута требует подтверждения. Действующие
ограничения на host для выбывшего активного адреса и резерва сохраняются.

Очереди стран остаются равноправными. Внутри очереди учитываются недавний
успех, серия отказов и сглаженная задержка. При наличии новых или восстановившихся
адресов для них резервируется как минимум один из пяти допусков. Остальные
места распределяются между группами источников по очереди.
Перед применением адрес проходит свежую проверку помощника и Chrome.
Схема, ограничения и владение файлом описаны в [ADR 0011](decisions/0011-endpoint-history.md).

## Локальная статистика источников

При поступлении пакета помощник отмечает страну запроса и группу поставщика для
каждого адреса. Балл появляется после завершённой проверки в поиске или при
первичном отборе в резерв. Отдельное подтверждение Chrome привязано к стране
набора, сессии, точному адресу и попытке подключения. Помощник держит учёт в
памяти текущей сессии. Исчерпание окна или лимита удаляет и запись, и её баллы.
Состояние карантина хранится отдельно.

Popup запрашивает только агрегаты по одной выбранной стране через уже открытый
порт Native Messaging. У чтения есть таймаут и привязка к поколению подключения.
Порядок отображения строк не меняет очередь проверки. Выбор политики и результаты
сравнения описаны в [решении об оценке источников](decisions/0012-source-quality.md).
