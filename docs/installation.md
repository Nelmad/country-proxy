# Установка, обновление и откат

[English setup and recovery](getting-started.md) · [Русское руководство](README.ru.md)

## Первая установка

Поддерживаемый путь stable — macOS и обычный профиль Chrome. Технические
ограничения — Chrome 120+ и Python 3.11+; это не означает, что каждая версия
диапазона прошла приёмку. Точная матрица — в [критериях stable](stable-readiness.md).
Для Linux есть установщик, но полный браузерный smoke пока не выполнен. Windows/Incognito не поддерживаются.
Node и Playwright нужны разработчику, а не пользователю расширения.

Для знакомства создайте отдельный профиль Chrome. Во время поиска блокируется
HTTP/HTTPS всего выбранного профиля, включая уже открытые вкладки и localhost.
Если рабочих адресов нет или нужно вернуть прежний маршрут, нажмите
**Отключить** в Country Proxy.

Для знакомства используйте профиль без личных аккаунтов. Публичный прокси
принадлежит третьей стороне: успешная проверка HTTPS и страны не подтверждает
добросовестность оператора, отсутствие логов или анонимность. Для чувствительных
действий используйте доверенное соединение. Это расширение профиля Chrome,
а не VPN для всей ОС. [Данные и разрешения (English)](getting-started.md#data-and-permissions).

1. Выберите выпуск на [GitHub Releases](https://github.com/Nelmad/country-proxy/releases).
   Скачайте приложенный `country-proxy-X.Y.Z.zip` и `.zip.sha256`.
   Автоматический `Source code (zip)` GitHub — другой архив; checksum нашего
   комплекта к нему не относится. Если Releases ещё нет, доступны только
   исходники или явно обозначенный локальный кандидат.
2. Проверьте скачанный архив в папке загрузки:

   ```sh
   shasum -a 256 -c country-proxy-X.Y.Z.zip.sha256
   ```

   Замените `X.Y.Z` номером выпуска. Контрольная сумма проверяет соответствие
   скачанных файлов; доверять нужно также источнику обоих файлов.
3. Распакуйте `country-proxy` в постоянное место. Не запускайте установку прямо
   из временной распаковки или папки, которую затем удалите/переименуете.
4. На Mac запустите `Install.command`. Он ищет Python 3.11+ среди обычных
   команд установки и versioned-команд `python3.14`–`python3.11` в PATH.
   Если подходящего Python нет, он сообщает об этом и завершает работу.
   Альтернативно из этой папки запустите установленный Python 3.11+, например:

   ```sh
   python3.14 scripts/install.py
   ```

   Установщик создаёт `.venv`, устанавливает `requirements.txt`, пишет launcher
   `.runtime/host-<ключ профиля>` и `local.country_proxy.json` для обычного Google Chrome.
   Локальная история помощника хранится в `.runtime/data/<ключ профиля>`.
   Здесь ключ вычисляется по корню Chrome `user-data-dir`, а не по вложенным
   `Default`/`Profile N`. Профили с одной регистрацией используют один каталог;
   отдельная история для каждого такого профиля не обещается.
   Установщик выводит точный путь. Для отдельного тестового профиля укажите
   и `--profile`, и `--data-dir` с путями к принадлежащим ему каталогам.
   Регистрация содержит абсолютный путь к launcher. Системный прокси и launchd
   не меняются. На Linux используется та же команда.
5. Откройте `chrome://extensions`, включите режим разработчика, загрузите
   распакованное расширение из `extension` **этого же комплекта**.
   Комплект использует разрешение `declarativeNetRequest` для удержания запросов
   вкладок до подтверждения прокси. Широкий доступ к содержимому сайтов не нужен.
6. Откройте выбор страны в popup и найдите её по русскому/английскому названию
   или ISO-коду. Нажатие на страну сразу запускает подключение. Новая установка
   не выбирает страну заранее; избранное можно оставить пустым. Нужен статус
   «Подключено»; если адресов нет, прочитайте [диагностику](runbook.md). Номер версии сам по себе не доказывает
   работоспособность подключения.

`python3 --version` может показывать старый системный Python даже при наличии
нового `python3.14`. Указывайте команду реально установленной подходящей версии;
не меняйте системный Python ради расширения.

### Отдельный Chrome for Testing

Для проверок используйте новый каталог `--user-data-dir` Chrome for Testing
и передайте **тот же** каталог установщику как `--profile`, а также отдельную
папку истории. Например, из папки комплекта:

```sh
./Install.command --profile "/absolute/path/to/test-profile" --data-dir "/absolute/path/to/test-history"
```

Здесь нужны ваши точные абсолютные пути. Это корень `user-data-dir`, а не
вложенная папка `Default`. Оба параметра обязательны для изолированной установки.
Без `--profile` установщик регистрирует помощник обычного Google Chrome.
Установщик выводит фактические пути регистрации и истории: проверьте их до запуска
расширения. Сам браузер установщик не открывает.

User-level Native Messaging registration ищется в `NativeMessagingHosts`
выбранного user-data-dir. Официальный [порядок поиска Chrome](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging#native-messaging-host-location)
проверен 16 ноября 2026; в приёмке используется CfT 151, без изменения регистрации
основного Chrome.

## Обновление без потери настроек

Автообновления из GitHub нет: текущая поставка — unpacked extension плюс локальный
помощник. Обновляйте их **вместе**, в прежней постоянной папке. Не удаляйте
расширение из Chrome и не генерируйте новый `manifest.key` — он фиксирует ID.

1. Прочитайте release notes, включая требования Python/Chrome, изменения настроек
   и откат. Запишите текущую версию и выбранные страны.
2. Скачайте и проверьте новый ZIP. Распакуйте во временную папку для проверки,
   но не запускайте оттуда установщик основного Chrome.
3. Нажмите **Отключить** в Country Proxy, затем временно выключите расширение
   переключателем в `chrome://extensions`. Не нажимайте «Удалить».
4. Сделайте локальную резервную копию установленного комплекта и сохраните старый
   ZIP/checksum. В прежней постоянной папке замените `extension/`, `native/`,
   `scripts/` и остальные поставляемые файлы **целиком** файлами нового комплекта.
   Не смешивайте остатки разных версий; не удаляйте `.venv`, `.runtime`, `.git`
   или другие пользовательские файлы. Если это developer checkout с правками,
   сначала отдельно сохраните их — поверх dirty checkout комплект не накладывается.
5. Из прежней постоянной папки снова запустите установщик. Он приводит зависимости
   к `requirements.txt` и обновляет launcher/регистрацию. Флаг `--skip-dependencies`
   не является стандартным обновлением: он оставляет прежние зависимости.
6. Включите расширение и нажмите **Reload / Перезагрузить**. Одного изменения
   manifest или перезапуска браузера недостаточно: ранее тест находил старые
   исполняемые скрипты при новом отображаемом номере версии.
   Если Chrome сообщает о новых разрешениях, проверьте запрос блокировки
   сетевых запросов (`declarativeNetRequest`) и включите обновлённое расширение.
7. Проверьте версию, выбранную страну, избранное, подключение и **Отключить**. Настройки
   `chrome.storage.local` остаются в профиле при сохранении расширения/ID;
   резерв строится заново. Если выпуск меняет схему настроек, следуйте его
   отдельной миграции. Последовательность сначала проверяется в тестовом профиле.

При обновлении с 0.2.0 прежний список стран становится избранным, а выбранная
страна сохраняется. Полный каталог доступен независимо от избранного.
Сохранение этого списка не перезапускает подключение. Новый режим нескольких
стран сохраняет отдельный разрешённый набор и восстанавливает его целиком после
перезапуска; старая одиночная настройка не становится набором автоматически.

Прокси-настройки Country Proxy действуют на весь выбранный профиль Chrome,
включая уже открытые вкладки.

## Откат

Перед заменой версии с удержанием трафика нажмите **Отключить** и дождитесь
статуса «Отключено». Это снимает сохранённые DNR-правила; предыдущий комплект
без этого механизма сам их не освобождает. Одно выключение расширения перед
заменой файлов не заменяет этот шаг. Если откат уже сделан без Stop и трафик
заблокирован, верните полный новый комплект с тем же ID, выполните Stop, затем
повторите откат. Профиль и пользовательские настройки удалять не требуется.

Комплект до появления режима нескольких стран не понимает этот набор. Перед
откатом переключитесь в **Одна страна**, явно выберите нужную страну, затем
нажмите **Отключить**. После отката выберите её снова. Не переносите включённый
множественный выбор в старый комплект; extension и helper обновляются вместе.

Перед возвратом к **0.2.0** сохраните в избранном хотя бы одну страну, включая
нужную для подключения после отката. В 0.2.0 этот список ограничивает меню, а
пустой список не поддерживается. После Reload выберите подготовленную страну
заново. Это условие относится к старой версии; в новой пустое избранное допустимо.

1. Отключите подключение и временно выключите расширение.
2. Если предыдущий комплект использует старый launcher `.runtime/host`, перед
   заменой файлов запустите **текущий** `python3 scripts/install.py --prepare-legacy-rollback`.
   Для тестовой установки добавьте её точный `--profile`. Проверьте выведенную
   регистрацию. Прежний помощник сможет запуститься. Файлы локальной истории
   сохранятся до следующего обновления; старый помощник без дисковой истории
   не загружает их и работает с памятью текущего процесса.
3. Восстановите предыдущий **полный комплект** по тому же пути, не удаляя расширение
   из Chrome и пользовательские настройки.
4. Запустите установщик предыдущего комплекта: откат Python-кода без отката
   зависимостей может не сработать.
5. Включите расширение, сделайте Reload, проверьте версию, подключение и отключение.

Если менялась несовместимая схема настроек, автоматический откат не обещается:
порядок восстановления должен быть в notes этого выпуска. Не копируйте целиком
профиль Chrome ради обычного обновления приложения.

## Если папка уже перемещена

Регистрация продолжит указывать на старый путь; установщик новой копии специально
откажется перезаписывать чужую регистрацию. Остановите расширение. Проверьте точный
`path` в **одном** `local.country_proxy.json`, сохраните его резервную копию и
удалите только устаревшую регистрацию. Затем запустите установщик из окончательной
папки. Это отдельная миграция пути; она не нужна при обычном обновлении на месте.
Изменение папки распакованного расширения также потребует действий в Chrome —
поэтому постоянный путь рекомендуется с первой установки.

Регистрация обычного Chrome:

- macOS: `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/local.country_proxy.json`.
- Linux: `~/.config/google-chrome/NativeMessagingHosts/local.country_proxy.json`.

## Удаление

Нажмите **Отключить**, удалите Country Proxy в `chrome://extensions`, затем удалите
только его `local.country_proxy.json` из указанного каталога. Папку приложения
с `.venv` и `.runtime` можно удалить отдельно; это удалит тестовые отчёты
и обычную локальную историю помощника в `.runtime/data`.
Внешний каталог, заданный через `--data-dir`, таким удалением не затрагивается;
удаляйте его отдельно только если он больше не нужен другим профилям.
Остальные регистрации, расширения и системные настройки не трогайте.

Стабильный ID задаёт [manifest key](https://developer.chrome.com/docs/extensions/reference/manifest/key).
Контракт и ограничения поставки — в [процессе релизов](releases.md).

## Проверяемые зависимости в кандидате 1.0.1

Стандартная установка проверяет SHA-256 всех загружаемых runtime wheels и
исходного архива помощника. Build backend закреплён отдельно в
`build-requirements.txt`; сборка проходит в одноразовом окружении, после чего
локальные wheels также устанавливаются с проверкой хешей. Конфигурация и
переменные окружения pip не могут подменить индекс или отключить эти проверки.
Интерпретатор Python и его bundled pip остаются предварительно установленной
доверенной основой. Хеши входов не означают побайтово одинаковую сборку wheel
на разных версиях Python.

Повторный запуск проверяет состав `.venv`; посторонние пакеты требуют отдельного
чистого комплекта, а не автоматического удаления пользовательских зависимостей.
Receipt `.runtime/dependency-install.json` хранит хеши lockfiles и wheels, без
секретов. `--skip-dependencies` предназначен для явного повторного использования
подготовленного окружения и не подтверждает установку по новому lockfile.

Существующий интерпретатор `.venv` и код уже установленного комплекта считаются
доверенными. Проверка путей и фактического `sys.prefix` защищает от ошибочно
выбранного или повреждённого окружения; она не аутентифицирует произвольную
локальную программу, подменённую под именем Python. Для недоверенного старого
комплекта используйте новый каталог и доверенный системный Python.
