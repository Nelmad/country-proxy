# Первый stable: границы и приёмка

Scope зафиксирован 16 ноября; статус обновлён **17 ноября 2026 года**.
Локальная runtime/offline-приёмка **1.0.0 закрыта** в заявленном scope:
**460 Python + 227 JS = 687 tests, structure PASS; 3 checks, 0 failures, 0 skipped**,
независимый runtime-review **GO**. Номер и датированный CHANGELOG определены.
Остаются точные reviewed release commit, source/ZIP identity и checksum;
export, hosted workflow и публикация — отдельные шаги со своим подтверждением. Процесс выпуска — [releases](releases.md),
проверки и ограничения — [verification](verification.md).

## Пользовательский результат и поддержка

Первый stable: macOS, обычный профиль Google Chrome, распакованное расширение
и локальный Python helper из одного комплекта. Пользователь выбирает страну
или равноправную группу; продукт ищет адрес, проверяет HTTPS и страну выхода,
подтверждает маршрут в Chrome и автоматически заменяет его при отказе.
Если подходящих адресов нет, поиск продолжается с безопасной блокировкой;
**Отключить** освобождает собственные настройки расширения.

Приёмка выполняется только в отдельном Chrome for Testing с отдельной
регистрацией helper и профилем. Основной Chrome не изменяется. Имеющееся
браузерное evidence получено на CfT 151.0.7922.34 и Python 3.14 на macOS:
это проверенная конфигурация, а не сертификация всего заявленного в README
диапазона Chrome 120+ / Python 3.11+. До stable фиксируются точные версии
приёмки и основание поддерживаемого диапазона; неподтверждённые нижние версии
не выдаются за проверенные.

Среда текущей чистой приёмки: macOS 26.6.2, Apple Silicon (arm64),
Chrome for Testing 151.0.7922.34, Python 3.14.7. Поддерживаемый пользовательский
путь — обычный профиль Chrome на macOS с обеими частями комплекта; результаты
на CfT указываются явно. Значения 120/3.11 в коде — пороги допуска, а не
свидетельство браузерной приёмки нижних версий. Проверка Gatekeeper для архива,
скачанного извне, и системного диалога выбора папки не покрывается автоматизацией.

Linux имеет установщик, но не входит в полную приёмку первого stable.
Windows, Incognito, Chrome Web Store, автообновление и работа без установленного
Python в этот scope не входят. Node/Playwright нужны для разработки, не пользователю.

## Стабильный договор

- **Выбор и настройки.** Одиночная страна либо непустой неупорядоченный набор
  стран; избранное отдельно от разрешённого набора. Порядок выбора и текущая
  страна не дают приоритета. Сохранение/редактирование группы без явного
  подключения не меняет маршрут; исправный адрес не ротируется по таймеру.
  `selectionMode`, `selected`/`selectedCountries`, избранное и сохранённые группы
  остаются в `chrome.storage.local` при сохранении ID расширения.
  Независимые правки избранного из popup и настроек не перезаписывают друг
  друга; для одной страны действует последнее принятое явное изменение.
  Импорт/экспорт групп использует `country-proxy/groups`, version 1, только названия и страны.
  Неверный сохранённый включённый набор даёт блокировку и понятную ошибку,
  а не молчаливое сокращение набора или выбор другой страны.
- **Helper.** Реальная проверка совместимости — `feedbackProtocol=1` в hello,
  start и status; confirm/reject привязаны к Session/generation, attempt и
  точному endpoint. Номер версии в hello информационный: равенство SemVer
  частей код не проверяет. Обновляются обе части одним комплектом; неправильный
  протокол блокирует подключение с предложением обновиться. Стабильный договор
  не обещает совместимость произвольных старых 0.x-комплектов; несовместимые
  изменения после stable требуют явной миграции и версии по [release policy](releases.md).
- **Локальная история.** Установщик задаёт `--data-dir` по корню Chrome
  `user-data-dir`/регистрации, а не по каждому `Default`/`Profile N`.
  Обычный путь — `.runtime/data/<ключ профиля>`; с явным тестовым `--profile`
  требуется явный `--data-dir`. Без него helper работает только в памяти.
  `history.mode` в hello/status различает `persistent`, `memory`, `busy` и
  `unavailable`; занятой или недоступный каталог не мешает поиску с временной
  историей в памяти. Настройки стран и избранного каждого профиля отдельны.
- **Проверка адреса.** Свежие HTTPS с доверенными сертификатами обязательны:
  Cloudflare 200 с глобальным exit IP и GeoIP-страной из выбранного набора,
  Google 204, затем проверка самого Chrome. «Подключено» означает подтверждённый
  браузером маршрут. До подтверждения новые обычные запросы удерживаются
  DNR gate, включая запросы страниц к тем же проверочным HTTPS-хостам.
  Gate не повторяет заблокированные формы и не отзывает уже отправленный трафик;
  границы — [ADR 0018](decisions/0018-preconfirmation-traffic-gate.md).
  TLS/HTTP/неверная страна/invalid trace не обходятся ради
  доступности. До двух резервов имеют другие host/exit; при исчерпании резерва
  продолжается поиск. Побеждает первый подходящий ответ; старый здоровый резерв
  вправе опередить новый.
- **Граница блокировки.** Во время поиска, проверки, замены и потери helper
  прямой HTTP/HTTPS, включая localhost, блокируется во всём обычном профиле,
  пока настройками управляет Country Proxy. Если управление перехватили policy
  или другое расширение, показывается ошибка; собственный DNR gate остаётся
  закрытым до Stop, а чужие proxy-настройки не переписываются.
  Расширение освобождает только собственный слой настроек; системный proxy не
  меняется. Это не VPN и не гарантия маршрутизации всего трафика ОС.
- **Stop и restart.** Отключение отменяет поиск/проверки; поздние ответы старого
  поколения не возвращают маршрут. Перезапуск восстанавливает явный разрешённый
  выбор и намерение enabled/off, заново проверяя соединение. Смена набора не
  допускает позднего применения адреса прежнего набора.
- **Установка и обновление.** Постоянная папка, стабильный `manifest.key`/ID,
  extension и helper вместе, зависимости через установщик, затем Reload.
  Существующие `.runtime`, настройки и история не стираются обычным обновлением;
  резерв строится заново. Откат — целым прежним комплектом с его зависимостями;
  перед возвратом к версии без групп нужен одиночный выбор и отключение.
  Точная последовательность — [installation](installation.md).

## Текущая дельта кандидата 1.0.0

После принятой MIT-сборки изменены `background.js`, `controller.js` и `popup.js`:
обработка ошибок при холодном восстановлении enabled-состояния и явный Retry.
Native, зависимости и установщик не менялись. Независимый source review закрыл
два обнаруженных случая: сокращение невалидного набора через Retry и получение
proxy-настроек после вторичной ошибки записи. Повторены 10 focused regressions,
восемь состояний popup проверены DOM adapter; это не браузерная приёмка.

**17 ноября: controlled CfT PASS, три сценария.** Холодное восстановление под
реальным rival с явным Retry полной AT/EE/NO; отдельный Stop/reconnect; смешанный
невалидный набор требует нового выбора до/после Stop. Popup и избранное доступны,
после освобождения rival нет автоматического захвата, ordinary HTTPS удерживается
до proof и проходит после обоих TLS-контролей. Финальный Stop снимает оба класса
DNR и собственные настройки; принадлежащие прогону процессы/профиль очищены,
регистрация основного Chrome неизменна.

Прогон использовал CfT 151.0.7922.34, локальные CONNECT/TLS, синтетическое native
предложение и GeoIP, manifest 0.2.1. Исполняемые worker scripts/popup совпали
с диском; 19 extension-файлов совпали до/после. Затем изменено только version
manifest на 1.0.0, key/permissions/production-код не менялись. Нового public
run/soak нет. Канонический offline contract 1.0.0 прошёл: 687 tests и structure
PASS; все 215 source hashes совпали до/после. После прогона обновлены только
два документа с результатами. Независимый runtime-review — GO.
Подробности — в [verification](verification.md); 680 tests остаются историческим MIT baseline.
Whole-extension identity прежних 29 файлов не заявляется для нынешней сборки.

## Решение о готовности и предел проверок

Stable принимается после закрытия pending и применимых строк матрицы, при
отсутствии воспроизводимых нарушений HTTPS/географии, direct-блокировки в границе
владения, сохранения настроек, отмены и очистки. Нехватка публичных адресов
отмечается отдельно как INCONCLUSIVE; она не превращает корректный механизм
в FAIL и не позволяет выдать недоказанное за PASS.

Не требуются два живых резерва всегда, доступность всех 249 стран, заданная
задержка публичной замены или успех конкретного нового адреса на второй/третьей
замене. Нет нового public-run/soak после каждой QA/docs правки: повторение
назначается по изменённому риску, [матрице releases](releases.md) и идентичности
поставляемых байтов. Дополнительная диагностика и платформы идут после этого scope.
