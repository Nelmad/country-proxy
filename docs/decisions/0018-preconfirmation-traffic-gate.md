# 0018 — Обычные запросы только после подтверждения Chrome

Принято 17 ноября 2026 года. Дополняет
[управление прямым прокси](0001-native-direct-proxy.md) и
[браузерную HTTPS-проверку](0014-browser-probe-latency.md).

Аудит воспроизвёл окно между применением candidate к обычному профилю и
завершением browser probe: обычная HTTPS-вкладка получила ответ, пока Chrome
ещё не подтвердил страну. Последующее отклонение неправильной страны работало,
но не отменяло уже отправленный запрос. Отсутствие DIRECT в proxy-настройках
не доказывало удержание трафика до подтверждения.

## Решение

Добавляется `declarativeNetRequest` без новых широких host permissions.
При включённом подключении динамические правила блокируют новые обычные
HTTP/HTTPS-запросы и WebSocket handshakes. Main-frame покрывается явно:
правило без `resourceTypes` по умолчанию его не включает.

Более высокий приоритет имеют только служебные GET/XHR самого расширения:
точные HTTPS URL Cloudflare trace и Google generate_204 с форматом параметров
существующего probe. Исключение ограничено initiator ID этого расширения.
Поскольку DNR сравнивает hostname инициатора, а не полную схему origin, URL
также содержит случайный UUID-маркер текущего удержания. Адаптер захватывает
его перед probe и добавляет только к валидным служебным URL, сохраняя параметры
fetch и запрещая передачу Referer. При новом hold маркер заменяется: прежний
fetcher не получает новый. Маркер не передаётся UI/native/storage и не
записывается в отчёты; он неизбежно присутствует в собственном DNR-правиле и
HTTPS URL двух доверенных сервисов.
Навигация вкладки и запрос страницы к тем же URL исключения не получают.
`allowAllRequests` и разрешение всего служебного домена не используются.

Обычный трафик разрешают отдельные session rules только после обоих успешных
HTTPS, допустимой страны, проверки действующего proxy route и актуальности
поколения/предложения. Перед новой проверкой, заменой маршрута или повторным
запуском разрешение закрывается. Mutation queue и проверка поколения не
позволяют старому завершению открыть новый candidate. Ошибка управления gate
не становится успехом соединения; отдельно предпринимается блокировка proxy.

Динамический закрытый gate сохраняется между запусками браузера и обновлениями;
session allow удаляется Chrome при shutdown/upgrade. При старте worker
оставшееся session allow снимается до восстановления подключения. Отключение
предпринимает очистку собственных proxy и privacy настроек независимо друг от
друга; gate снимается после подтверждённого освобождения proxy. Если proxy
очистить не удалось, gate остаётся закрытым, чтобы не открыть candidate.
Частичный неуспех отображается как незавершённое отключение.

Если proxy-настройки перехватило другое расширение/политика, Country Proxy
не переписывает их, снимает статус подключения и сохраняет свой gate до
явного **Отключить**. Это намеренное изменение прежнего поведения: наличие
чужого DIRECT само по себе больше не разрешает обычный трафик включённой сессии.

## Пользовательская граница

Блокировка отклоняет новые сетевые запросы; она не хранит очередь и не
отправляет заново формы/платежи после подключения. После подтверждения сайт
может повторить запрос или пользователь может обновить страницу.
Уже отправленные запросы и ранее открытые соединения не отзываются задним
числом. Локальные ответы из cache/service worker и привилегированные запросы
Chrome/других расширений имеют границы DNR API. Это не VPN и не обещание
изоляции всех сетевых протоколов операционной системы.

Нативные проверки, TLS/certificates, два HTTPS-сервиса, страна и общий deadline
browser probe не меняются. Все страны выбранного набора равноправны.

## Установка и откат

Новое разрешение позволяет Chrome блокировать запросы, не читать их содержимое.
Перед откатом на комплект без gate необходимо выполнить **Отключить** в
текущей версии и дождаться «Отключено»: предыдущий код не умеет освобождать
сохранённые DNR-правила новой версии. Выключение расширения в менеджере Chrome
приостанавливает его действие, но не заменяет нормальное завершение Stop перед
заменой комплекта. ID и формат пользовательского выбора не меняются.

## Проверка

Приёмка должна воспроизвести старое окно, затем проверить ordinary navigation
и fetch во время ожидания, к тем же служебным URL и другому origin; успешный
выход NO/EE/AT, неверную страну, HTTP/TLS/timeout, повторную замену,
Stop/late response, restart, ownership и ошибки/отмену мутаций gate.
Исполняемые скрипты и ZIP фиксируются; local TLS/GeoIP fixtures не выдаются
за публичную географию. Результаты — [verification](../verification.md).

Источник API, проверен 17 ноября 2026:
[Chrome declarativeNetRequest](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest).
