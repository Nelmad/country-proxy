# 0013 — Поиск одновременно с проверкой резерва

Принято 14 ноября 2026 года. Дополняет
[параллельную проверку резервов](0010-parallel-reserve-checks.md).
Даже два параллельно проверяемых резерва могут занять сетевой таймаут, прежде
чем помощник начнёт искать новые адреса. Восстановление запускает обе работы
одновременно: перепроверку готовых записей и один проход общего потокового поиска.

Первый допустимый результат становится предложением Chrome. Страна текущего
маршрута, порядок выбранных стран и происхождение адреса не задают приоритет.
Нужны прежние проверки HTTPS, принадлежности выбранному набору, карантина и
отличия от прежнего маршрута по серверу и выходному IP. Проверка в Chrome
по-прежнему обязательна; native-успех не означает, что маршрут подключён.

Один владелец управляет обеими ветками. До передачи результата он отменяет и
дожидается завершения проигравшей ветки. Общий потоковый планировщик не запускает
два прохода одновременно. При наличии резерва новые проверки занимают не более
восьми из десяти общих слотов; два остаются для перепроверок. Начальный поиск без
резерва может использовать десять. Одинаковые адресные проверки не дублируются.

Если несколько проверок успели успешно завершиться, независимый второй результат
можно сохранить в резерв с временем его фактического окончания, даже если
ветка ещё завершала отмену остальных задач. После завершения отмены победитель
проверяется повторно; если он устарел, используется следующий допустимый
завершённый результат. Отмена незавершённой проверки не обновляет срок жизни и
не является отказом адреса. Устаревший результат после отключения или смены
набора не становится новым предложением.

После подтверждения нового адреса браузером обслуживание, как и прежде,
возобновляется, а свободные места пополняются. Теперь освобождение места при
действующем маршруте также будит пополнение, не задерживая
его до следующего периодического прохода. Пустая попытка сохраняет обычный
интервал повторения; изменение счётчиков и успешная перепроверка сами по себе
не запускают частый повторный поиск. До подтверждения Chrome пополнение закрыто.

Таймауты HTTPS, два отказа health перед заменой и срок жизни резерва не меняются.
Ускорение измеряется после начала восстановления; время обнаружения отказа
показывается отдельно. Контролируемый стенд не доказывает доступность публичных
прокси или максимальный срок восстановления в интернете.
