# 0010 — Параллельная проверка резервов перед заменой

Принято 1 ноября 2026 года. При последовательной проверке первый резерв мог
занять весь сетевой таймаут, хотя второй уже отвечал. Помощник теперь запускает
проверку обоих свежих адресов одновременно. Первый успешный ответ внутри
выбранного набора становится кандидатом для Chrome. Сетевые таймауты и число
проверок активного адреса остаются прежними.

Перед передачей победителя Chrome помощник дожидается завершения или отмены
обеих проверок. Для уже проверенного второго адреса срок свежести отсчитывается
от фактического окончания его проверки. Если проверка второго была прервана,
помощник сохраняет исходный срок. Перед каждой следующей попыткой применения
адрес проходит новую проверку. Действуют прежние ограничения на страну,
совпадающие серверы и выходные IP. [Правила свежести](0008-independent-reserve-maintenance.md).

Маршрут Chrome общий для профиля, поэтому браузер пробует только один адрес за раз.
Помощник присваивает каждому предложенному адресу номер попытки внутри сессии.
Ответы `confirm` и `reject` содержат ID сессии, номер попытки и
протокол/IP/порт. Отказ дополнительно содержит наблюдаемую причину. Запоздалый
ответ для прежнего предложения игнорируется. Команда ручной замены передаёт
намерение пользователя отдельно.

Пока Chrome проверяет предложение, помощник продолжает обслуживать имеющиеся
резервы. Загрузку новых для пополнения он возобновляет после подтверждения.
Если Chrome отклонит адрес, оставшийся свежий резерв можно использовать сразу.
При запуске обе стороны сверяют `feedbackProtocol` до начала поиска. При
несовместимости расширение показывает ошибку с инструкцией по обновлению.

Если Chrome применил часть настроек и вернул ошибку, расширение останавливает
помощник, пробует восстановить блокирующий маршрут и показывает ошибку в popup.
Эта локальная ошибка не учитывается как отказ адреса. При неудаче самой
блокировки это прямо указывается в статусе.
