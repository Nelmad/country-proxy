## Восстановление

`tests/recovery.mjs`, запуск 14:05 UTC: подключение EE → закрытие и перезапуск браузера → автоматический новый подбор; временное отсутствие регистрации Native Messaging → явный статус и блокировка сети; возврат регистрации → автоматическое подключение. При отключении освобождены proxy, WebRTC policy и network prediction. Всё PASS, отчёт `.runtime/recovery-report.json`.

Набор состояний failover проверен детерминированными тестами с двумя последовательными сбоями и browser rejection. Искусственное отключение реального стороннего прокси не выполнялось. Этот сценарий выполнялся до загрузки расширения в основной профиль; его отдельная проверка описана ниже.

Ограничения: не проверены Linux, Windows, Incognito (отключён), все 249 стран и доступность произвольных сайтов. SOCKS5 поддерживается кодом/источниками, но в последнем полном Chrome smoke были выбраны HTTP и SOCKS4. Скриншоты и отчёты не включаются в переносимый архив.

## Основной профиль Chrome

По явному запросу владельца 2026-10-27, около 17:20–17:22 МСК, расширение загружено через chrome://extensions в основной Chrome и закреплено на панели. Выбрана NO, автоматический подбор завершился статусом «Подключено». Обычная вкладка HTTPS Cloudflare trace подтвердила loc=NO и TLS 1.3; тест прошёл с настоящими пользовательскими расширениями. Локальные проверки заняли 17–23 секунды. Один запрос сначала вернул ERR_CONNECTION_RESET, затем страница успешно открылась — это краткая проверка, а не подтверждение длительной стабильности. Подключение оставлено включённым для пользовательского испытания.

Снимок подтверждения хранится только в `.runtime/main-profile-no.png`. Предыдущие разделы описывают исходный isolated smoke до установки в основной профиль.
