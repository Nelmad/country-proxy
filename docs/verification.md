## 0.2.0: причина сохранённого профиля и резерв, 2026-10-28

Chromium Debugger.getScriptSource подтвердил, что `.runtime/chrome-test`
исполнял старые background.js/controller.js. В старом onProxyError был только
native check, а одинаковый активный адрес принимался без повторного browser
probe. Поэтому при исправном upstream и сломанном Chrome route замена не
начиналась. Фактически исполняемые хэши не совпадали с исходниками. Даже после
смены manifest на 0.2.0 runtime.getManifest показывал новый номер при старых
скриптах. Это установленная причина, а не предположение о состоянии профиля.

Reload только тестового расширения обновил оба исполняемых скрипта. Затем
сохранённый профиль автоматически восстановил подключение после перезапуска и
прошёл отказ браузерного маршрута при живом native upstream: PASS, 1,7 с до B.
Во всех сетевых тестах теперь сверяются фактические скрипты через
`tests/chrome-runtime.mjs`; чтение файлов через fetch вместо этого не используется.
Сохранённый сценарий умеет обновить только тестовое расширение и повторно
проверить fingerprint после Reload и перезапуска.

Добавлен резерв до двух адресов с отличающимися host/exitIp, одной страной,
TTL 90 секунд, фоновым обслуживанием и перепроверкой перед использованием.
Резервные события не заменяют статус подключения. Пополнение ограничено тремя
параллельными проверками и 45 секундами за раунд; stop и смена страны отменяют
задачи. Исправлена гонка: browser rotate, пришедший во время native health,
не теряется после позднего успешного результата.

Два Chrome-сценария с заранее готовым резервом прошли:

| Профиль/сбой | Автоматический резерв | Время до B |
| --- | --- | --- |
| Свежий профиль, физическое закрытие listener/соединений A | PASS, без полного поиска | 37,2 с |
| Сохранённый профиль после Reload и перезапуска, сломан только browser route | PASS, без полного поиска | 37,6 с |

До и после — обычная HTTPS-вкладка с той же фактической страной PL; все
наблюдаемые маршруты fixed_servers, ошибки fatal, запрос после отказа не прошёл
напрямую. Время включает обнаружение и проверки, это не обещание мгновенного
переключения. Скриншот готового резерва просмотрен: «Резерв: 1 из 2 · проверен
помощником». Тестовый host использует два loopback-порта с общим реальным
выходным IP; только для этих fixtures идентичность endpoint/исключения задаётся
портом. Production host/exitIp deduplication проверяется отдельными unit-тестами.
TLS и GeoIP настоящие; эти PASS не доказывают два публичных норвежских IP.

Дополнительный live NO запуск новой версии: за 240 секунд не подтвердился даже
исходный адрес, итог INCONCLUSIVE / No verified baseline proxy. Инъекция отказа
не выполнялась, успешный публичный NO A→B не заявляется. Тестовый браузер закрыт.

Регистрация сохранённого тестового профиля восстановлена, временные профили
