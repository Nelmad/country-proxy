# Как выбранные страны получают места для проверок

Модель задаёт порядок допуска стран при ограниченном числе проверок. Она
использует логическое время и искусственные адреса. Тот же контракт проверяется
отдельно на [рабочем планировщике](../native/stream_search.py). Результаты
проверки HTTPS и фактического маршрута в Chrome приведены в [отчёте](verification.md).

## Алгоритм и границы

- Выбранный набор из `N=1..249` стран получает одну случайную перестановку —
  устойчивое кольцо на поколение. Порядок пользовательского выбора и названия ISO
  не задают приоритет. В модели кольцо вводится явно для воспроизводимости.
- Credit cursor выдаёт **120 последовательных tickets по кольцу** и сдвигается
  на `120 mod N` после каждого round. При `N≤120` это `floor(120/N)` каждой
  стране и остаток по продолжающемуся курсору. При `N>120` ticket получают
  очередные 120 стран. Каждый ticket разрешает один уникальный admission.
- Discovery cursor независим от credit cursor и использует то же кольцо. Он
  сдвигается ровно на одну страну при **фактическом старте** country job.
  Одновременно jobs не больше трёх; завершение освобождает место для следующего.
  Страна посещается не более одного раза за round. Курсоры не сбрасываются и
  не пересортировываются при новом round, timeout, порядке ответа источников
  или перестановке входного списка того же выбранного набора.
- Producer имеет discovery window 45 секунд. Его неиспользованные credits
  защищены до completion/timeout. После завершения сначала обслуживается его
  готовая очередь; только оставшиеся credits могут быть отданы другим.
  Результат, поступивший точно на deadline или позднее, не принят этим producer.
- Accepted pending queue переживает rounds независимо от payload-cache.
  Не больше 120 ссылок на endpoint на страну, максимум `249×120=29 880` ссылок
  и не больше столько же уникальных записей. Новая выдача не вытесняет уже
  принятую голову; переполнение возвращает backpressure/drop, не обещание
  проверки конкретного отброшенного endpoint. Country promise сохраняется,
  поскольку заполненная очередь уже содержит работу этой страны.
- Endpoint, известный сразу нескольким странам, имеет одну запись. Его
  фактический checker start обслуживает всех уже известных owners и расходует
  один admission. Дубликат не превращается в дополнительные HTTPS-проверки.
  Повторная выдача уже допущенного endpoint ждёт следующего round.
- Admissions не равны запускам. FIFO checker queue использует не больше десяти
  slots. Только получение свободного slot создаёт `checker_start`. Каждый
  admission имеет до двух конечных проверок (fast/slow), то есть максимум
  120 admissions / 240 checker starts за round. Модель ограничивает каждую
  длительность сверху 47 секундами и моделирует только продолжающийся поиск:
  успешного подключения, которое остановило бы поиск, здесь нет.
- 45 секунд заканчивают discovery, а не checker. Round включает drain всех
  допущенных проверок. Следующий round начинается после drain. Это определение
  нужно для нижеследующего bound; **45 секунд не являются временем round**.

## Точная формула и доказательство

`B_discovery(N) = ceil(N/3)` rounds от начала непрерывного обхода: каждый round
начинает хотя бы `min(3,N)` доступных country jobs, даже если все они зависли.
Это гарантия начала запроса, а не получения адреса. Backoff, отсутствие доступных
источников и остановленный поиск не удовлетворяют этой предпосылке.

**`B_probe(N) = 1 + ceil(N/120)`**, если считать включительно round, в котором
страна получила готовый допустимый pending candidate. Иначе: не более
`ceil(N/120)` следующих полных rounds. Страна с неизрасходованным credit получает
admission и реальный checker start уже в текущем drain-round.

Предпосылки: выбранный набор и поколение не меняются; поиск непрерывен; готовая
очередь сохраняется до предоставленного turn; в ней остаётся допустимый endpoint;
у checker есть конечное завершение и продолжается обслуживание его очереди.
Bound обещает **хотя бы одну начатую проверку для страны**, а не каждую запись
очереди, пригодный прокси, частоту подключений или время в секундах.

Доказательство:

1. Текущий partial round мог уже израсходовать все tickets этой страны или не
   дать ей ticket. Поэтому его нельзя считать полной возможностью обслуживания.
2. Tickets следующих `k=ceil(N/120)` rounds — один непрерывный участок длины
   `120k≥N` в повторяющемся кольце. В нём встречается каждая страна независимо
   от стартового cursor. Это не требует совпадения discovery и credit cursor.
3. Сохранённый готовый endpoint использует собственный ticket до donation.
   Если другой owner уже запустил checker того же endpoint, страна тоже
   обслужена. Иначе endpoint получает admission в предоставленном round.
4. В очереди этого round не больше 240 конечных checker attempts, у них десять
   обслуживаемых slots; новые rounds не вклиниваются перед ними. Поэтому
   admission приводит к реальному checker start до завершения drain-round.

| N | B_discovery | B_probe, включая partial ready round |
|---|---:|---:|
| 1 | 1 | 2 |
| 2 | 1 | 2 |
| 3 | 1 | 2 |
| 120 | 40 | 2 |
| 121 | 41 | 3 |
| 249 | 83 | 4 |

Bound `B_probe` достижим, а не только удобная верхняя оценка. В adversarial test
страна в конце первого credit-window тратит свою долю, затем в 44.9 секунды
получает новый адрес. Все конкурирующие очереди насыщены, donation отсутствует.
При `N=249` эта страна отсутствует в следующих двух windows и реально запускает
checker только в четвёртом round, считая round появления. Для каждого N из
таблицы тест подтверждает соответствующее точное значение по checker events.

## Проверки и честные ограничения

`test_fairness_model.py` проверяет фактические checker starts, а не только
массивы credits: все N из таблицы, разные начальные cursors, fast A/late B,
насыщение десяти slots, slow retry, готовность без credit, overflow retention,
обход висящих discovery jobs, dedup и предел 240 starts. Перестановки selection
не меняют trace; переименование ISO с соответствующим переименованием
случайного кольца сохраняет trace при равном качестве. Это coupling случайности,
а не требование одинакового numeric seed после сортировки иных названий ISO.

Проверено Python 3.14, stdlib only; синтаксис и API совместимы с Python 3.11.

[Тесты рабочего планировщика](../tests/test_stream_search.py) воспроизводят
границы для 1, 2, 3, 120, 121 и 249 стран по фактическому старту проверки.
Они также проверяют позднюю группу поставщиков, общий лимит зеркал, сохранение
курсора между проходами и поздние дубликаты. [Тесты источников](../tests/test_stream_sources.py)
проверяют число одновременных запросов, размер ответов, повторное использование
загрузки и завершение задач при отмене.

Изменение credit step, сброс курсоров, ограничение pending только cache размером
160 без отдельного retention, ранняя передача credits ещё работающей страны
или отбрасывание допущенной проверки ровно на 45-й секунде разрушают предпосылки.
Такие изменения требуют нового доказательства и новых тестов до реализации.
